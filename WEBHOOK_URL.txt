Le tunnel Cloudflare décrit ici auparavant était mort (HTTP 000, vérifié le
2026-07-25). Seul ngrok tourne, sous PM2, sur un domaine statique qui survit
aux redémarrages.

  Base       : https://directed-ladder-chatter.ngrok-free.dev
  Health     : /health                    (libre, pour le monitoring)
  Webhook    : /webhook/<WEBHOOK_TOKEN>   ← à coller dans l'alerte TradingView
  Signaux    : /signals/<WEBHOOK_TOKEN>
  Push Pine  : /push-pine/<WEBHOOK_TOKEN>

Le jeton est dans .env (jamais versionné). Pour obtenir l'URL complète :

  grep ^WEBHOOK_TOKEN= .env | cut -d= -f2 | \
    xargs -I{} echo "https://directed-ladder-chatter.ngrok-free.dev/webhook/{}"

POURQUOI UN JETON DANS L'URL
-----------------------------
TradingView n'autorise aucun en-tête personnalisé sur une alerte : ni signature
HMAC, ni Authorization. Le secret doit donc voyager dans le chemin.

Une liste blanche d'IP ne fonctionnerait pas non plus : le tunnel se connecte à
localhost, Flask voit donc 127.0.0.1 pour chaque requête, et l'IP réelle n'est
lisible que dans X-Forwarded-For — en-tête que n'importe qui peut forger.

Le serveur écoute sur 127.0.0.1 uniquement (plus sur 0.0.0.0) : le tunnel tourne
sur cette machine, rien de légitime n'a besoin d'un accès depuis le réseau local.

Un jeton invalide reçoit 404, pas 403 : une route protégée et une route
inexistante doivent être indiscernables pour qui sonde le tunnel.

ROTATION DU JETON
-----------------
  1. openssl rand -hex 24
  2. remplacer WEBHOOK_TOKEN dans .env
  3. pm2 restart killingbot-webhook
  4. mettre à jour l'URL dans les alertes TradingView
